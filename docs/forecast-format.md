# 예보 자료 구조

기상청 날씨누리 공개 페이지에서 무엇을, 어디서, 어떤 모양으로 가져오는지 정리한다.
API 키·결제 없이 동작하며, robots.txt 가 `User-Agent: * / Allow: /` 로 이 경로들을 허용한다.

## 출처와 담당 구간

| 자료 | 경로 | 커버 | 수집 방식 |
|---|---|---|---|
| 예보 통보문 | `/w/forecast/notice.do?stnId=` | D+0 ~ D+3 | requests + BeautifulSoup |
| 중기예보 | `/w/forecast/overall/mid-term.do?stnId1=` | D+4 ~ D+10 | requests + BeautifulSoup |
| 동네예보 | `/w/rss/dfs/hr1-forecast.do?zone=` | D+0 ~ D+3 | RSS (XML) |
| 행정동 목록 | `/w/rest/zone/dong.do` | — | JSON, 하루 캐시 |
| 지상일기도 | `/w/repositary/image/cht/img/{종류}_{YYYYMMDDHH}.png` | 최근 2일 | 정적 PNG |
| 1개월 전망 | `/repositary/xml/fct/mon/img/fct_mon1rss_108_{YYYYMMDD}.xml` | 4주 | RSS (XML) |

두 예보가 겹치는 날은 **통보문이 이긴다** (더 가까운 날이라 정확하다).

## 자료형

`ScrapedDay` (`src/kma_scrape.py`) → 검증 후 `DayForecast` (`src/forecast.py`)

| 필드 | 의미 | 없을 수 있나 |
|---|---|---|
| `date` | 날짜 | 아니오 |
| `tmin_lo` / `tmin_hi` | 아침 최저기온의 **지역 간 분포 범위** | 예 |
| `tmax_lo` / `tmax_hi` | 낮 최고기온의 분포 범위 | 예 |
| `sky` | 하늘상태 (`맑음`·`구름많음`·`흐림`·`흐림, 비` …) | 예 |
| `pop` | 강수확률 % | **예 — D+0~D+3 은 대개 없다** |
| `source` | `통보문` 또는 `중기예보` | 아니오 |

### 기온은 하루의 최저/최고가 아니다

`tmin_lo=14, tmin_hi=22` 는 "아침 최저가 14도에서 22도까지 변한다"가 아니라
**전국 각지의 아침 최저기온이 그 범위에 걸쳐 있다**는 뜻이다. 단일 도시를 조회하면
`lo == hi` 가 된다. 이 의미를 뒤집으면 예보를 정반대로 전하게 된다.

### 강수확률이 비는 이유

통보문 표에는 **기온과 파고만** 있다. 하늘상태는 예보관 서술문에서 뽑아 채우지만
(`daily_sky()`), 강수확률은 어디에도 없어 `None` 으로 남긴다. 없는 값을 지어내지 않는다.
중기예보 구간(D+4~)은 표에 강수확률이 있어 그대로 나온다.

## 1개월 전망은 값이 아니라 확률이다

10일 예보 너머는 성격이 다르다.

| | 일별 예보 | 1개월 전망 |
|---|---|---|
| 단위 | 하루 | 주 |
| 내용 | "낮 30℃, 맑음" | "평년보다 높을 확률 50%" |

매주 목요일 발표하며 파일명에 발표일이 박혀 있다. `_latest_xml()` 이 하루씩 거슬러
올라가며 최근 21일 안의 최신본을 찾는다.

XML 구조에 주의할 점이 둘 있다.

- `<description>` 아래가 `summary` / `weather_forecast` / `onemonth_ta_forecast` /
  `onemonth_rn_forecast` 로 한 겹 더 중첩돼 있다. `findall`(직계)이 아니라
  `iter`(전체)로 찾아야 한다.
- 지역별 확률은 `local_ta_name` 이 지역 수만큼 반복되고 그 순서대로 `minVal`/
  `similarVal`/`maxVal` 이 따라온다. 이름으로 인덱스를 찾아 같은 위치의 값을 집는다.
- 지역명 표기가 예보 페이지와 다르다 (`서울ㆍ인천ㆍ경기도` — 가운뎃점이 아니라 `ㆍ`).
  `REGION_ALIAS` 가 매핑한다.

## 예보관 서술

표에 없는 것 — 태풍, 특보, 기압계 배경 — 은 서술문에 문장으로 들어 있다.

```
□ (종합) 아침 기온 낮아 쌀쌀, 당분간 낮과 밤의 기온차 크겠음
○ (내일, 13일) 대체로 흐리다가 오후부터 구름많음, 늦은 새벽부터 아침 사이 곳에 따라 빗방울
○ (기온) 이번 예보기간 아침 기온은 14~20℃, 낮 기온은 27~29℃로 평년과 비슷하겠습니다.
```

- `□ (종합)` 은 한 줄 요약. 슬랙 본문 1문단의 '왜 그런지' 로 쓴다.
- `○ (날짜)` 줄에서 날짜별 하늘상태를 파싱한다 (`daily_sky()`).
  비·눈이 언급되면 그것을 우선한다 — 우산 여부가 갈리는 정보다. `빗방울` 같은 약한
  표현도 비로 본다.
- 괄호 머리말이 원본 게시물의 `초반 (9월 1일~2일):` 과 같은 모양이라, 주간 게시 카드의
  불릿 라벨로 그대로 쓴다.

## 지역 구분

```
전국 · 수도권 · 강원 · 영서 · 영동 · 충남 · 충북 · 전남 · 전북 · 경남 · 경북 · 제주
```

- 통보문은 구역별 페이지가 따로 있어 `stnId` 하나로 끝난다.
- 중기예보는 두 구역을 한 페이지에 묶어 준다(예: 부산·경남 + 대구·경북). 기온표의
  `rowspan` 지역 그룹을 이어 나르며 해당 구역 행만 골라낸다 (`Region.mid_group`).
- `영동`·`영서` 는 중기예보가 `강원도 영동`/`강원도 영서` 로 실제 나눠 주는 구역이다.
  값이 다르게 나온다.
- `중부`·`남부`·`영남`·`호남`·`충청` 은 대응 페이지가 없어 대표 구역으로 보내되,
  `resolve_region()` 이 안내문을 함께 돌려준다. 조용히 바꿔치기하지 않는다.

## 검증과 실패 처리

페이지 구조가 바뀌면 파싱이 조용히 틀어진다. 세 겹으로 막는다 (`src/forecast.py`).

1. **범위 검증** — 기온 −35~45℃, 강수확률 0~100 밖은 버린다. `lo > hi` 면 바로잡고,
   아침 구간이 통째로 낮 구간보다 높으면 아침/낮을 맞바꾼다.
2. **날짜 정렬** — 무엇이 오든 요청한 창에 매핑하고, 빠진 날은 경고를 남긴다.
3. **게시 포기** — 7일 중 4일 이상 기온이 비면 예외를 던져 **아무것도 올리지 않는다.**

| 상황 | 동작 |
|---|---|
| 통보문 500 | 중기예보만으로 응답 |
| 일기도 없는 시각 | 404 가 아니라 200+HTML 이 오므로 매직바이트로 판별 후 12시간 전으로 |
| 동네예보 RSS 중단 | 광역 구역으로 안내 (2025-03-31 폐지 공지가 났던 경로) |
| 지역 후보 여럿 | 단정하지 않고 되묻는다 — 강릉에도 강남동이 있다 |

## 발표 시각

| 자료 | 발표 |
|---|---|
| 통보문 | 05 · 11 · 17 · 23시 |
| 중기예보 | 06 · 18시 |
| 동네예보 | 매시 |
| 지상일기도 | 00 · 12 UTC (09 · 21시 KST) |

캐시 TTL 은 예보 1시간, 행정동 목록 24시간이다. 기상청은 하루 네 번만 갱신하므로
멘션마다 긁을 이유가 없고, 남의 서버에 대한 예의이기도 하다.
