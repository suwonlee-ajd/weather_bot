# 날씨 문장 문체 기준

날씨를 사람이 읽을 문장으로 옮길 때의 기준. 사람이 쓰든, 모델이 쓰든, 코드가 내든 같은 기준을 따름.

- 봇의 조언 문구 — [`src/advice/phrases.py`](../src/advice/phrases.py) 의 문구 표(`*_LINES`, 특이사항은 `SPECIAL`)와
  [`src/advice/rules.py`](../src/advice/rules.py) 의 임계값
- 주간 게시 본문 — [`src/weekly/body.py`](../src/weekly/body.py) 의 규칙 기반 본문과 [`src/weekly/writer.py`](../src/weekly/writer.py) 의 모델 지시문(`SYSTEM`)

**기준은 하나.** 이 문서를 고쳤으면 위 파일도 같이 볼 것 — 한쪽만 고치면 사람이 쓰는 답변과
봇이 내는 문구가 조용히 갈라짐.

## 순서 — 날씨 자체를 먼저

**알고 싶은 것은 "그래서 날씨가 어떤가" 임.** 확률·수치를 앞세우지 말고 하늘상태와 기온부터
말한 뒤, 확률은 뒤에 덧붙임.

- ✅ "수요일은 맑고 낮 최고 30도까지 오릅니다. (강수확률 10%)"
- ❌ "수요일 강수확률 10%, 기온 13~30도입니다."

비가 관건인 날은 예외 — 비가 오는지가 그날의 날씨 자체이므로 먼저 말함.

## 지어내지 않기

- 수치는 기상청 원문이므로 **그대로 옮김.** 추정해서 채우지 않음.
- 태풍·특보는 예보관 서술(`□`/`○` 줄)에 있음. 거기 없으면 "해당 없음"이라고 답함.
- 조회가 실패하면 지어내지 말고 실패했다고 말함.
- 근거가 없으면 **침묵함.** 조언은 있으면 좋은 것이지 반드시 채울 칸이 아님.

## 같은 말 반복하지 않기

날씨는 매일 비슷해서, 기준 없이 쓰면 **날짜와 숫자만 바뀐 같은 문장**이 나옴.
같은 조건이라도 표현을 바꿈.

```
✅ 일교차 14도 → "낮엔 반팔, 아침저녁엔 겉옷이 필요한 날입니다."
✅ 일교차 12도 → "아침저녁으로 12도 차이가 납니다. 낮 기준으로만 입으면 아침에 춥습니다."
❌ 둘 다      → "일교차가 N도 안팎으로 벌어집니다. 겉옷 하나 걸치시고..."
```

일교차 11도 이하는 짚지 않음 — 초가을의 평범한 날이라 매일 같은 말이 됨.

한 답변 안에서도 마찬가지. 여러 날을 말할 때 "~하겠습니다"만 늘어놓지 말고,
날짜별로 문장 길이와 서술을 달리함.

## 조언은 그날의 특징에서 나옴

수치를 조언으로 옮길 때, **그 수치가 하루를 어떻게 만드는지**를 말함.

기준은 `src/advice/rules.py` 의 상수와 같음.

| 신호 | 기준 | 말할 것 |
|---|---|---|
| 예보관 서술의 특이사항 | 태풍·한파·폭염·너울·풍랑·황사·안개·건조 (`SPECIAL`) | 수치 조언보다 **앞에** 둠. 문장 안에서 해당자(해안가·산지·운전 등)를 짚음 |
| 일교차 큼 | 12도↑ (`BIG_SPREAD`) | 옷차림 — 낮 기준인지 아침 기준인지 |
| 추위 | 아침 최저 5도↓ (`COLD_MORNING`, 기상청 한파특보 기준이 아니라 자체 기준) | 방한·실내 온도 |
| 폭염 | 낮 최고 33도↑ (`HEAT_WAVE`) | 한낮 바깥 활동 자제·수분 |
| 더움 | 낮 최고 30도↑ (`WARM_DAY`) | 얇은 옷·수분 |
| 쌀쌀 | 아침 최저 10도↓ (`CHILLY_MORNING`) | 가벼운 겉옷 |
| 비 | 강수확률 60%↑ (`RAIN_LIKELY`) 또는 하늘상태에 비·눈·소나기 | 우산. 시간대가 있으면 함께 |

- 한파·폭염·더움·쌀쌀은 이 순서로 **하나만** 고름.
- 광역 예보의 가까운 날(D+0~D+3)은 강수확률이 없어 비 신호가 하늘상태에서만 나옴.

여러 개 걸려도 **두세 개까지만.** 다 붙이면 무엇이 중요한지 사라짐.

## 기온 읽는 법 — '지역 간 분포 범위'

`아침 14~22℃` 는 하루의 최저/최고가 **아님.** 전국 각지의 아침 최저기온이 14℃에서
22℃ 사이에 걸쳐 있다는 뜻. 낮 기온도 마찬가지. 이 의미를 뒤집어 말하지 않음.

한 지역만 물었으면 그 지역 값을 씀. 전국 범위를 지역 답변에 그대로 옮기지 않음.

일교차는 «N도 안팎» 으로 씀(«까지» 아님). 아침·낮 범위의 가운데 값끼리 뺀 수라 어느 한 곳의
실제 일교차가 아님. 예: "*10/8(목)에는* 일교차가 16도 안팎으로 벌어지겠습니다."

## 단풍 — 관측과 예상을 섞지 않음

단풍 자료는 출처가 둘. 기상청은 **지금 어느 단계인지(관측)** 만 알리고, 날짜를 미리
말하는 것은 웨더아이의 **예상**. 문장마다 어느 쪽인지 드러냄.

- ✅ "설악산은 9/28에 첫단풍이 관측됐습니다(기상청). 절정은 10/25로 예상됩니다(웨더아이)."
- ❌ "설악산 단풍은 10/25에 절정입니다." — 예상을 사실처럼 말했음
- ❌ "기상청에 따르면 절정은 10/25입니다." — 기상청은 예상일을 내지 않음

- 첫단풍은 산 정상부터 20%, 절정은 80%가 물든 때. 처음 묻는 사람에게는 한 번 짚어 줌
  (봇은 누가 처음인지 몰라 산별 답마다 꼬리말로 붙임).
- 예상일이 지났는데 관측이 없으면 "10/25 예상이었지만 아직 관측되지 않았습니다" 라고 씀.
  늦어졌다고 단정하지 않음 — 관측 담당자가 사진을 올리기 전일 수도 있음.
- 산 날씨는 **산 아래 마을** 의 동네예보. 산 위는 더 춥고 바람이 세다는 점을 붙임.
- 기상청 21곳에 없는 산은 모른다고 답함. 가까운 산의 값으로 대신하지 않음.
- 9월 둘째 주 ~ 11월 둘째 주 밖이면 단풍을 다루지 않음.

## 톤

채널 공지에 어울리는 **담백한 존댓말.** 과장·이모지 남발·호들갑을 피함.

- ✅ "내일 아침 쌀쌀합니다. 겉옷 챙기세요."
- ❌ "😱 헉! 내일 완전 추워요!! 패딩 필수!!!"

단, 위험 신호(폭염·한파·태풍·호우특보)는 **분명하게** 전함. 담백함이 위험을
흐리는 쪽으로 가면 안 됨.

## 길이

사람이 쓰는 답 기준. 봇의 멘션 답은 여기에 머리글·조언·예보관 서술 인용·출처 줄이 더 붙음.

- 하루 질문 → 2~4줄
- 주간 질문 → 날짜별 한 줄씩 + 조언 두세 줄

슬랙 게시는 본문 두 문단(1문단 날씨, 2문단 조언) + 철 소식 문단(단풍·첫눈·벚꽃) + 출처 줄. 상세는
카드 이미지에. 1문단 끝은 모델이 쓰면 «~사오니» 같은 연결어미, 규칙 기반이면 문장으로 맺음 —
규칙 기반 2문단은 «사실. 권하는 말.» 꼴의 조언이라 앞 문단을 이어받지 못함.

묻지 않은 날짜는 넣지 않음. "모레"를 물었으면 모레를 답함.
