# 예보 자료 구조

기상청 날씨누리 공개 페이지에서 무엇을, 어디서, 어떤 모양으로 가져오는지 정리함.
API 키·결제 없이 동작하며, robots.txt 가 `User-Agent: * / Allow: /` 로 이 경로들을 허용함.

## 출처와 담당 구간

| 자료 | 경로 | 커버 | 수집 방식 |
|---|---|---|---|
| 예보 통보문 | `/w/forecast/notice.do?stnId=` | D+0 ~ D+3 (오전 발표 기준 — 2026-10-06 11시 발표로 확인) | requests + BeautifulSoup |
| 중기예보 | `/w/forecast/overall/mid-term.do?stnId1=` | D+4 ~ D+10 | requests + BeautifulSoup |
| 동네예보 | `/w/rss/dfs/hr1-forecast.do?zone=` | 02~14시 발표 D+0 ~ D+3, 17·20·23시 발표 D+4 까지 (기상청 단기예보 기간, 2024-11-28 확대. 끝날의 00시 한 점은 버림). 오늘은 발표 이후 남은 시간만 있어 답에 «N시 이후» 를 붙이고, 23시 발표부터는 오늘 값이 없어 내일부터 보임 | RSS (XML) |
| 행정동 목록 | `/w/rest/zone/dong.do` | — | JSON, 하루 캐시 |
| 지상일기도 | `/w/repositary/image/cht/img/{종류}_{YYYYMMDDHH}.png` | 최근 2일 | 정적 PNG |
| 태풍정보 | `/w/repositary/xml/typ/raw/DAOU/RTKO63/RTKO63.tbl` → 태풍마다 경로표 `.osp` | 진행 중인 태풍의 지난·현재 위치와 예상 진로 | 정적 텍스트 (CSV) |
| 1개월 전망 | `/repositary/xml/fct/mon/img/fct_mon1rss_108_{YYYYMMDD}.xml` | 4주 | RSS (XML) |
| 단풍 현황 | `kma.go.kr/kma/theme/maple_photojs.jsp?treeType=4&obsPlace=` | 9/20 무렵~11월 | JSONP |
| 단풍 예상 | 웨더아이 공지 「YYYY년 단풍 예상시기」 첨부 PDF | 한 해 한 번 | PDF 표 (pypdf) |

| 벚꽃 예상 | 웨더아이 공지 「YYYY년 벚꽃 개화예상시기」 첨부 PDF | 한 해 한 번 (2월 말) | PDF 표 (pypdf) |

두 예보가 겹치는 날은 **통보문이 이김** (더 가까운 날이라 정확함). 오전 발표끼리는 겹치지 않고,
겹칠 때는 그날 값을 통째로 통보문 것으로 바꿈 — 중기예보의 강수확률·하늘상태도 함께 사라짐.

## 자료형

`ScrapedDay` (`src/kma/page.py`) → 검증 후 `DayForecast` (`src/weekly/forecast.py`)

| 필드 | 의미 | 없을 수 있나 |
|---|---|---|
| `date` | 날짜 | 아니오 |
| `tmin_lo` / `tmin_hi` | 아침 최저기온의 **지역 간 분포 범위** | 예 |
| `tmax_lo` / `tmax_hi` | 낮 최고기온의 분포 범위 | 예 |
| `sky` | 하늘상태 (`맑음`·`구름많음`·`흐림`·`흐림, 비` …) | 예 |
| `pop` | 강수확률 % | **예 — 통보문이 덮는 날(D+0~D+3)은 늘 없음** |
| `source` | `통보문` 또는 `중기예보` | 아니오 |
| `cities` | 도시 → (아침 최저, 낮 최고). 중기예보 표의 도시별 값 그대로(구역 행만, 범위 밖 값이 든 도시는 뺌) | **예 — 통보문 날은 늘 비어 있음** (통보문 표는 전국 범위뿐) |

### 기온은 하루의 최저/최고가 아님

`tmin_lo=14, tmin_hi=22` 는 "아침 최저가 14도에서 22도까지 변한다"가 아니라
**전국 각지의 아침 최저기온이 그 범위에 걸쳐 있다**는 뜻. 단일 도시를 조회하면
`lo == hi` 가 됨. 이 의미를 뒤집으면 예보를 정반대로 전하게 됨.

### 강수확률이 비는 이유

통보문 표에는 **기온과 파고만** 있음. 하늘상태는 예보관 서술문에서 뽑아 채우지만
(`daily_sky()`), 강수확률은 어디에도 없어 `None` 으로 남김. 없는 값을 지어내지 않음.
중기예보 구간(D+4~)은 표에 강수확률이 있어 그대로 나옴. 단, 통보문과 겹친 날은 통보문 값으로
통째로 바뀌어 강수확률이 빔.

## 1개월 전망은 값이 아니라 확률

10일 예보 너머는 성격이 다름.

| | 일별 예보 | 1개월 전망 |
|---|---|---|
| 단위 | 하루 | 주 |
| 내용 | "낮 30℃, 맑음" | "평년보다 높을 확률 50%" |

매주 목요일 발표하며 파일명에 발표일이 박혀 있음. `_latest_xml()` 이 하루씩 거슬러
올라가며 최근 21일 안의 최신본을 찾음.

XML 구조에 주의할 점이 셋 있음.

- `<description>` 안의 `<body>` 아래가 `summary` / `weather_forecast` / `onemonth_ta_forecast` /
  `onemonth_rn_forecast` 로 한 겹 더 중첩돼 있음. `findall`(직계)이 아니라
  `iter`(전체)로 찾아야 함.
- 지역별 확률은 `local_ta_name` 이 지역 수만큼 반복되고 그 순서대로 `minVal`/
  `similarVal`/`maxVal` 이 따라옴. 이름으로 인덱스를 찾아 같은 위치의 값을 집음.
- 지역명 표기가 예보 페이지와 다름 (`서울ㆍ인천ㆍ경기도` — 가운뎃점이 아니라 `ㆍ`).
  `REGION_ALIAS` 가 매핑함.

## 단풍은 관측과 예상이 다른 곳에서 옴

기상청은 단풍 시기를 **예보하지 않음.** 21개 명산이 지금 어느 단계인지 관측해 알릴 뿐임.
예상일은 민간 업체 웨더아이가 해마다 9월 첫 주에 냄(2023-09-07, 2024-09-06,
2025-09-05, 2026-09-04). 둘을 섞어 쓰지 않음 — 지도에서는 관측을 굵게, 예상을 흐리게,
멘션 답에서는 "관측"/"예상" 을 날짜 옆에 적음.

| | 기상청 현황 | 웨더아이 예상 |
|---|---|---|
| 곳 | 21곳 (`src/season/foliage/mountains.py`) | 15곳 — 14곳이 겹치고 금강산은 뺌 |
| 값 | 단풍전 · 첫단풍 · 절정, 관측일 | 첫단풍 · 절정 예상일 |
| 기준 | 정상부터 20% 첫단풍, 80% 절정 | 같음 |

**기상청 현황** (`src/season/foliage/data.py`) — `applyMapleData({...})` 꼴의 JSONP. `places[]` 에 21곳의
단계(`status` 글자, `sts` 1~3)가, `flower` 에 `obsPlace` 로 고른 한 곳의 촬영일
(`bfShotDate` 단풍전 / `cfShotDate` 첫단풍 / `ffShotDate` 절정)이 옴. 산마다 날짜를 보려면
따로 불러야 해서, 물들기 시작한 산만 부르고 단계가 바뀌기 전까지 캐시함.
`isService` 가 거짓이면(서비스 기간 밖) **지난 시즌의 단계가 그대로 남아 있으므로** 전부 단풍전으로
읽고, 촬영일도 올해 것만 받음.

**웨더아이 예상** — 공지 목록에서 「{올해}년 단풍 예상시기」 게시물을 찾아 첨부 PDF 의
[첨부1] 표를 읽음. 날짜 표기가 `09.27`(~2024) → `10/3`(2025~) 으로 바뀐 적이 있어 둘 다 받음.
잘못 읽은 날짜는 그럴듯해 보여 알아채기 어려우므로, 한 줄이라도 어긋나면(9/1~12/15 밖,
절정이 첫단풍보다 이름, 10곳 미만) **표를 통째로 버리고 현황만 씀.**

봇이 단풍을 다루는 기간은 정해 두지 않고 **자료가 정함** — 기상청이 관측하는 동안(`isService`)과,
관측 전 올해 웨더아이 첫 예상일(가장 이른 첫단풍)까지(`Snapshot.showing`). 첫 예상일이 지났는데 서비스가
꺼져 있으면 관측을 접은 것으로 봄 — «아직 시작 안 함» 이라고 말하지 않게. 그 밖에는 단풍을
물어도 관측 기간이 아니라고 답함. 멘션에서 꽃 개화는 다루지 않음(벚꽃은 주간 게시에만).

## 벚꽃은 웨더아이 도시 예상만 실음

단풍과 같은 짜임(`src/season/blossom/`, 도시 좌표는 `spots.py`). 주간 게시의 벚꽃 문단과 지도에만 씀.

| | 기상청 봄꽃 목록 | 웨더아이 예상 |
|---|---|---|
| 대상 | 벚꽃 군락지 13곳 (여의도 윤중로, 진해 여좌천 …) | 주요 도시 19곳 (기상관서 표준목) |
| 값 | 개화 전 · 개화 · 만발, 서비스 중인지(`isService`) | 개화 예상일 + 평년 개화일 |
| 쓰는 곳 | 다룰 때인지만 — 글·지도에 싣지 않음 | 문단(이번 주 · 올해/평년)과 지도 |

**기상청 군락지 관측은 싣지 않음**(사용자 결정) — 장소 이름이 낯설어 읽는 사람에게 닿지 않음. 목록
(`applyFlowerData({...})`)은 한 번만 받아 `isService` 로 철인지만 봄. 군락지별 촬영일(`obsPlace` 상세)은 받지 않음.

**지도** — 한 장, 도시 기준. 표지는 단풍 지도와 같은 짜임 — 예상일이 이번 주 뒤면 회색 빈 원(개화 예상 전),
이번 주면 옅은 🌸 와 점선 고리(이번 주 개화 예상), 지났으면 🌸(개화 예상일 지남). 라벨은 «서울 4/3», 이번 주는
굵게, 지난 곳은 흐리게. 범례는 지도에 나온 표지만. 올해 표가 없어 평년을 빌렸으면 표지는 같고 낱말만 «평년 개화일».
서울·수원, 청주·대전은 20~22px 거리라 🌸 를 단풍(20px)보다 조금 작게(18px) 그리고 고리도 붙여 그림.

**웨더아이 예상** — 「{올해}년 벚꽃 개화예상시기」 게시물의 PDF [첨부1] 주요도시 표. 날짜 표기가
`3.24`(~2024) → `3/25`(2025~) 로 바뀌었고, 2023 표에는 `4. 1` 처럼 띄어 쓴 날짜도 있음.
군락지 표는 이름이 두 낱말이라 읽지 않음. 3/1~4/30 밖이거나 15곳 미만이면 통째로 버림.
게시일은 머리 표의 날짜 칸(`#124c78`)에서 읽음 — 2026 게시물은 작성자 칸이 비어 있음.

발표가 2/21~2/28 이라(2023 2/28, 2024 2/23, 2025 2/21, 2026 2/26) 다루는 기간의 첫 주와
엇갈림. 올해 표가 아직 없으면 **지난해 표의 평년 개화일**을 빌려 "평년에는 서귀포 3/24 무렵
시작해 서울 4/8 무렵" 으로 전함. 평년값은 해마다 같음.

봇이 벚꽃을 다루는 기간도 **자료가 정함** — 기상청이 관측하는 동안(`isService`)과, 관측 전 올해
웨더아이 첫 개화 예상일까지(`blossom.data.showing`). 지난해 표의 평년은 기상청이 관측 중일 때만 받아 실음.
철이어도 웨더아이 표가 올해·지난해 모두 없으면 실을 것이 없어 벚꽃 문단을 빼고, 웨더아이 수집이 실패하면
영역 실패로 올림(`weekly/pipeline` 이 경고를 남기고 뺌).

## 첫눈은 관측만 있음

`src/season/snow/` (지점 24곳은 `stations.py`). 기상청은 첫눈을 예보하지 않고, 웨더아이도 예상을 내지 않음. 그래서
**관측 · 평년 · 그 주 예보의 눈** 셋으로 전함.

| | 값 | 출처 |
|---|---|---|
| 관측 | 24곳의 올 시즌 첫눈 날짜 | 기상자료개방포털 계절관측 조회 화면 |
| 평년 | 1991~2020 평년 첫눈 (서울 11/20 · 부산 12/23, 홍성은 없음) | 같은 포털의 평년값 xlsx — 코드에 박아 둠 |
| 신호 | 하늘상태의 «눈» · «비/눈» · «눈/비» | 이미 받는 광역·동네예보 |

**계절관측 조회 화면** — `seasonObsDataList.do?pgmNo=648&stnIds=_108,…&elementCds=DB006403&startDt=&endDt=`
을 GET 하면 키·로그인 없이 HTML 표가 옴(CSV·Excel 내려받기만 로그인이 필요함). 함정이 셋 있음.

- 지점마다 `<dt><b>지점</b></dt><dd>서울</dd>` 뒤에 표 하나. 표 caption 은 «코스모스, 매화…» 같은
  고정 문구라 지점을 알 수 없음 — 머리의 지점 이름으로 짝지음
- «년도» 는 그해 가을부터 이듬해 봄까지의 시즌(계절관측지침). 부산 2025년의 첫눈이 2026-02-07.
  아직 안 왔으면 표머리만 오고 행이 없음
- 안동 2026년 행에 `2026-01-10` 처럼 시즌 밖 날짜가 들어 있기도 함 — **시작일이 그 년도 8/1 이후일
  때만** 첫눈으로 읽음

관측자가 눈으로 보고 정하며 진눈깨비도 첫눈임. 2015년부터 교대근무 관서 24곳만 관측함.
관측 당일 조회에 반영됨(2026-10-29 서울 첫서리가 그날 오전 조회에 들어 있었음). 화면을 긁는
방식이라 구조가 바뀌면 지점 표를 하나도 못 읽어 `SnowError` 로 드러남 — 그때는 API허브
(`sfc_ssn.php`, 인증키 필요)로 옮김.

봇이 첫눈을 다루는 기간도 정해 두지 않고 **새 소식이 있을 때만** 다룸(`snow.data.showing`) —
지난 7일 안에 첫눈이 관측됐거나, 아직인 지점이 남았는데 예보에 눈이 있을 때. 주간 게시는 24곳 전체와
그 주 예보로, 지역 날씨 답의 한 줄은 그 지역 지점과 답에 보인 날의 예보로 가름.

## 장마·더위는 따로 받지 않음

`src/season/monsoon/` · `src/season/heat/`. 주간 게시가 이미 받은 그 주 예보(기온 분포 · 하늘상태 · 강수확률 ·
예보관 서술)만 읽음. 예보관 서술 인용은 공통(`src/season/narrative.py`) — 글머리(`□`·`○`)만 떼고 괄호 머리말은
남겨 그대로 옮기고, 통보문 줄이 먼저, 둘까지. 규칙 기반 본문 1문단이 이미 인용한 `(종합)` 줄은 되풀이하지 않음.
한 줄이 300자를 넘기도 해서 120자(`QUOTE_CHARS`)를 넘으면 낱말 경계에서 자르고 «…» 를 붙임 — 앞부분은 원문 그대로.

**더위** — 기상청 기상자료개방포털 기후통계의 정의를 기준으로 씀.

| 기준 | 기상청 정의 | 읽는 값 |
|---|---|---|
| 폭염 33℃↑ | 폭염일수 «일 최고기온이 33℃ 이상인 날» (`/climate/heatWave/selectHeatWaveChart.do?pgmNo=674`) | 낮 최고 분포의 위쪽 끝 `tmax_hi` |
| 열대야 25℃↑ | 열대야일수 «밤최저기온이 25℃ 이상인 날», 밤은 당일 18:01~익일 09:00 (`/climate/tropicalNight/selectTropicalNightChart.do?pgmNo=675`) | 아침 최저 분포의 위쪽 끝 `tmin_hi` |

- 분포의 위쪽 끝이 기준에 닿았다는 것은 **어딘가 한 곳 이상**이 닿는다는 뜻 — 그래서 «일부 지역» 이라고 씀
- 아침 최저는 전날 밤부터 그날 아침까지의 최저라 열대야의 밤에 가장 가까운 값. «그날 아침» 으로 적음
- 33℃ 는 폭염특보 기준이 아님 — 특보는 체감온도 기준이라 다름. 특보는 예보관 서술에 있을 때 그 문장으로만 전함
- 다룰 때: 기준에 닿는 날이 있거나 예보관 서술에 «폭염»·«열대야» 가 있을 때
- 문단·지도 머리 줄은 날짜를 이어진 구간으로 줄임 — «7/19(월)~7/25(일) 7일 · 최고 37℃ 7/24(토)». 날마다의 값은 늘어놓지 않음
- **더위 지도**(`heat/map.py`, 도시 좌표 `heat/cities.py`) — 중기예보 도시 표의 41곳(전국 페이지)을 그 표가 덮는 날만
  그림. 월요일 아침 게시면 금~일 — 통보문(D+0~D+3)은 도시별 값이 없어 그리지 않고, 지도 머리와 꼬리말에 그 기간을
  밝힘. 도시마다 그 기간 낮 최고 중 가장 높은 값을 적고, 33℃↑ 은 🥵, 그 밖은 다른 지도의 «없음·아직» 과 같은 회색 빈 원.
  라벨은 더운 곳부터 다른 표지·라벨과 겹치지 않는 자리에만 닮(자리가 없으면 뺌). 옆 표는 기준(낮 33℃↑ 또는 아침
  25℃↑)에 닿는 도시를 낮 최고 순으로 20곳까지 — 값과 그 요일, 기준에 닿는 값은 굵게. 도시별 값이 없는 주는 글만

**장마** — 기상청은 장마 시작·종료일을 철 중에는 «잠정» 으로만 말하고 철이 끝난 뒤(9월 무렵) 사후 분석으로
확정함. 확정값은 기상자료개방포털 «장마» 통계(`/climate/rainySeason/selectRainySeasonList.do` — 중부·남부·제주의
시작·종료·기간·강수일수·강수량, 1973~)에 오르지만 철이 지난 뒤라 주간 게시에 쓸 수 없음. 키 없이 철 중에 받을 수
있는 구조화된 자료가 없어(2026-11 확인) 예보관 서술로 전함.

- 다룰 때: 예보관 서술에 «장마»·«정체전선» 이 있을 때. 비가 잦아도 언급이 없으면 다루지 않음
- 제목은 «장마» 라는 말이 있을 때만 «이번 주 장마», 정체전선만이면 «이번 주 정체전선» — 정체전선은 봄·가을에도 걸림
- 비 오는 날: 하늘상태에 «비»·«소나기» 가 있거나 강수확률이 본문 조언과 같은 문턱(`RAIN_LIKELY` 60%) 이상인 날
- 시작·종료일을 말하지 않고, 그 까닭을 출처 줄에 밝힘

## 태풍은 날씨누리 지도가 읽는 파일에서

`src/season/typhoon/data.py`. 태풍 페이지(`/w/hazard/typhoon/report.do` 통보문 · `/w/typhoon/ko/weather/typhoon_02.jsp`
지도)는 진행 중인 태풍이 없으면 «현재 발표된 태풍(열대저압부)정보가 없습니다» 만 보여 주고, 지도는 JS 가
정적 파일을 읽어 그림. 그 파일을 그대로 받음 — 칸 뜻과 현재·예상 구분은 지도 스크립트
(`share/js/typhoon/typhoonContent.js` 의 `loadTlb` · `loadTyphoon`) 와 같게 읽음.

| 파일 | 모양 |
|---|---|
| 목록 `RTKO63.tbl` | 태풍 하나에 한 줄 `경로표,진로선`. **진행 중인 태풍이 없으면 200 + 0바이트** (2026-11-16 확인) |
| 경로표 `RTKO63_{발표시각 YYYYMMDDHHMM}_….osp` | 첫 줄 `2019,2,우딥,WUTIP`(연도·번호·이름·영문), 다음 줄부터 19칸 — 시각 · 위도 · 경도 · 위치 설명 · 진행 방향 · 이동 속도 · 중심기압 · 최대풍속 · 종류 · 강풍·폭풍 반경 … · 70% 확률반경 · 연관 열대저압부 |

함정이 넷 있음.

- 목록의 경로는 `/repositary/…` 인데 실제 자리는 `/w/repositary/…` — 지도 스크립트도 같은 치환을 함.
  없는 경로는 404 가 아니라 200 + HTML 오류 페이지가 오므로 `<` 로 시작하면 `TyphoonError`
- 지난·현재·예상 칸이 따로 없음. **70% 확률반경이 0 이면 지난·현재, 비었거나 0보다 크면 예상** — 예상 앞의
  마지막 위치가 현재. 같은 시각이 두 줄이면 뒤의 것. 끝에 `,,,,,,,0,…` 꼴의 빈 줄이 붙어 옴
- 태풍이 약해져도 목록에 남음. 종류 `TD`·`LOW` 나 연관 칸 `TD-END`·`LOW-END` 면 지도와 같은 문구
  («열대저압부로 약화» · «온대저기압으로 변질») 를 붙임. 연관 칸이 찬 앞쪽 `TD` 줄은 태풍이 되기 전 기록
- 발표시각은 경로표 파일 이름에만 있음. 경로표 한글의 인코딩은 태풍이 없을 때 만들어 확인하지 못함 — UTF-8 이
  아니면 CP949 로 읽음. 파서 고정 자료는 지도 스크립트 주석에 실린 2019년 제2호 우딥 경로표

강도와 크기는 파일에 없음 — 지도가 최대풍속으로 강도(표에는 «강도 1~5», 예전 이름 중·강·매우강·초강력)를,
강풍반경으로 크기(소형~초대형)를 매기는 것이라 옮기지 않고 중심기압·최대풍속만 그대로 씀.
열대저압부 목록(`RTKO64.tbl`)은 읽지 않음.

주간 게시의 태풍 문단은 **예보관 서술에 «태풍» 이 있고 목록에도 태풍이 있을 때만** 실림. 예보관이 말하지 않는
먼 태풍(괌 근처 등)은 싣지 않고, 그때는 태풍정보도 받지 않음.
현재(이름 · 위치 · 중심기압 · 최대풍속 · 시각), 예상(그 주 일요일 안의 마지막 예상 위치), 이번 주(예보관 서술에서
«태풍» 이 든 줄 둘까지, 통보문 먼저, 본문이 이미 인용한 줄은 빼고, 원문 그대로 — 길면 120자에서 «…»). 목록이 비면
서술에 «태풍» 이 있어도 싣지 않음 — 발생 가능성만 말하는 줄일 수 있고, 본문 조언(`SPECIAL`)이 이미 짚음.
태풍정보를 받지 못하면 서술의 태풍 줄만 실음(그릴 경로가 없어 지도도 없음).

**예상 경로 지도** (`src/season/typhoon/`) — 날씨누리에는 내려받을 경로 그림이 없음. 태풍 지도와 지난 태풍
화면은 브라우저가 경로표·WMS 타일로 그리는 OpenLayers 화면이고, 태풍마다 남는 정적 파일은 통보문 PDF
(`/w/repositary/xml/typ/pdf/`)뿐임(2026-11-16 지도 스크립트로 확인). 그래서 받은 경로표로 직접 그림.

- 지난 경로(회색 실선) · 현재 위치(빨간 점과 고리) · 예상 위치(점선 위 빈 원 — 이번 주 안은 진하게, 그 뒤는 옅게)
- 현재·예상 위치마다 «20일 15시 990hPa» 처럼 시각과 중심기압. 붙은 점끼리 글자가 겹치면 뒤의 것을 뺌
- 반경은 **경로표에 값이 있을 때만** 그리고 범례도 그만큼 — 예상 위치의 70% 확률반경(파랑), 현재 위치의
  강풍반경(초속 15m↑, 노랑)·폭풍반경(초속 25m↑, 빨강). 예외 방위·반경은 원에 넣지 않고 머리 줄에 원문대로
  («강풍반경 280km(남서쪽 230km)»)
- 기압선(등압선)은 경로표에 없어 그리지 않음 — 꼬리말에 기상청 지상일기도를 보라고 적음(일기도 영역이 빠진 주에도 맞는 말)
- 바탕은 Natural Earth 1:50m 육지를 95~180°E · 5°S~55°N 로 잘라 간소화한 `pacific_land.json`, 한국은 시도 윤곽
  (`korea_provinces.json`)으로 진하게 칠함. 범위는 경로·반경과 한국을 다 담게 맞추고 카드에 맞게 짧은 쪽을 넓힘
  (높이 380~560px). 태풍이 여럿이면 한 장에 다 그림

## 예보관 서술

표에 없는 것 — 특보, 기압계 배경, 태풍이 우리나라에 미칠 영향 — 은 서술문에 문장으로 들어 있음.

```
□ (종합) 아침 기온 낮아 쌀쌀, 당분간 낮과 밤의 기온차 크겠음
○ (내일, 13일) 대체로 흐리다가 오후부터 구름많음, 늦은 새벽부터 아침 사이 곳에 따라 빗방울
○ (기온) 이번 예보기간 아침 기온은 14~20℃, 낮 기온은 27~29℃로 평년과 비슷하겠습니다.
```

- `□ (종합)` 은 한 줄 요약. 슬랙 본문 1문단의 '왜 그런지' 로 씀.
- `○ (날짜)` 줄에서 날짜별 하늘상태를 파싱함 (`daily_sky()`).
  비·눈이 언급되면 그것을 우선함 — 우산 여부가 갈리는 정보. `빗방울` 같은 약한
  표현도 비로 봄.
- 괄호 머리말이 원본 게시물의 `초반 (9월 1일~2일):` 과 같은 모양이라, 주간 게시 카드의
  불릿 라벨로 그대로 씀.

## 지역 구분

```
전국 · 수도권 · 강원 · 영서 · 영동 · 충남 · 충북 · 전남 · 전북 · 경남 · 경북 · 제주
```

- 통보문은 구역별 페이지가 따로 있어 `stnId` 하나로 끝남.
- 중기예보는 두 구역을 한 페이지에 묶어 줌(예: 부산·경남 + 대구·경북). 기온표의
  `rowspan` 지역 그룹을 이어 나르며 해당 구역 행만 골라냄 (`Region.mid_group`).
- `영동`·`영서` 는 중기예보가 `강원도 영동`/`강원도 영서` 로 실제 나눠 주는 구역.
  값이 다르게 나오는 것은 중기예보 구간(D+4~)뿐임 — 통보문은 `강원`·`영서`·`영동` 모두 같은
  `stnId=105` 라 D+0~D+3 값이 같음.
- `중부`·`남부`·`영남`·`호남`·`충청` 은 대응 페이지가 없어 대표 구역으로 보내되,
  `resolve_region()` 이 안내문을 함께 돌려줌. 조용히 바꿔치기하지 않음.

## 검증과 실패 처리

페이지 구조가 바뀌면 파싱이 조용히 틀어짐. 세 겹으로 막음 (`src/weekly/forecast.py`).

1. **범위 검증** — 기온 −35~45℃, 강수확률 0~100 밖은 버림. 아침·낮 범위 각각 `lo > hi` 면
   바로잡음.
2. **날짜 정렬** — 무엇이 오든 요청한 창에 매핑하고, 빠진 날은 경고를 남김.
3. **게시 포기** — 7일 중 4일 이상 기온이 비면 예외를 던져 **아무것도 올리지 않음.**

| 상황 | 동작 |
|---|---|
| 통보문 500 | 멘션은 중기예보 구간(D+4~)만으로 응답. 주간 게시는 월~목 4일이 비어 게시를 포기함 |
| 중기예보 500 | 멘션은 통보문 구간(D+0~D+3)만으로 응답. 주간 게시는 금~일이 빈 채로 나감(빈 날 3일까지 허용) |
| 일기도 없는 시각 | 404 가 아니라 200+HTML 이 오므로 매직바이트로 판별 후 12시간 전으로 |
| 동네예보 RSS 중단 | 광역 구역으로 안내 (2025-03-31 폐지 공지가 났던 경로) |
| 지역 후보 여럿 | 단정하지 않고 되물음 — 강릉에도 강남동이 있음 |
| 단풍 현황 실패 | 멘션은 기상청 페이지를 안내, 주간 게시는 단풍 문단과 지도를 빼고 나감 |
| 단풍 지도 실패 | 주간 게시는 단풍 문단만 남김 |
| 벚꽃 관측 기간 실패 | 기상청이 관측 중인지 몰라 웨더아이 첫 개화 예상일 전까지만 다룸 |
| 벚꽃 예상 실패 | 실을 것이 웨더아이 도시 예상뿐이라 벚꽃 문단 없이 나감 |
| 벚꽃 지도 실패 | 주간 게시는 벚꽃 문단만 남김 |
| 첫눈 관측 실패 | 멘션은 기상자료개방포털 페이지를 안내, 지역 날씨 답은 첫눈 한 줄 없이, 주간 게시는 첫눈 문단과 지도를 빼고 나감 |
| 첫눈 지도 실패 | 주간 게시는 첫눈 문단만 남김 |
| 장마·더위 | 따로 받지 않아 실패할 곳이 날씨뿐 — 날씨가 실패하면 게시 자체를 건너뜀. 더위 지도를 못 그리면 더위 문단만 남김 |
| 태풍정보 실패 | 예보관 서술에 태풍 줄이 있으면 그 줄만으로 태풍 문단을 싣고, 없으면 태풍 문단 없이 나감 |
| 웨더아이 표 이상 | 예상을 버리고 현황만 그림. 30분 동안은 다시 받지 않음 |

단풍 현황 1시간(실패하면 2분 뒤 다시 봄), 단풍 예상 24시간(아직 안 올라왔거나 읽다 실패하면 30분),
첫눈 관측 1시간(실패하면 2분), 태풍정보 30분(실패하면 2분). 첫눈은 날씨 답마다 붙는 덧말이라 멘션 봇은 5초만 기다리고, 주간 게시는 20초.
산별 단풍 날짜는 단계가 바뀔 때까지 들고 있되, 그 단계의 촬영일이 아직 없으면
캐시하지 않고 다음 조회 때 다시 봄. 동네예보 RSS 와 기상청 벚꽃 목록은 캐시하지 않음. 광역 예보(통보문·중기예보)는
하루 네 번만 갱신하므로 멘션마다 긁을 이유가 없고, 남의 서버에 대한 예의이기도 함.

웨더아이 예상표(단풍·벚꽃)는 읽은 해의 것을 디스크(`data/cache/weatheri-{foliage,blossom}-{해}.json`,
`src/common/store.py`)에 남겨 다시 받지 않음 — 주간 게시가 철 밖에도 매주 돌아, 남기지 않으면 해마다 목록·게시물·PDF 를
수십 번 받음. 아직 안 올라왔거나 읽다 실패한 해는 남기지 않음. 위 24시간 메모리 캐시는 그 앞에서 멘션마다 파일을 읽지 않게 함.
